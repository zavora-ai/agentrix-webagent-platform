How a presentation is built

  • An owner-approved script in the signed release: chapters, must-say ("pricing is a pilot hypothesis"), must-not-say (client names, dates), sources, maximum length.
  • Adaptive fill from the release for this visitor's question ("40 WordPress sites").
  • Stage cues drive the real page: scroll, highlight, dim. They only ever target anchors in the current release.
  • Questions pause the tour, get a cited answer, then it resumes at the cue.

Budgets

  1. <2 sFirst chapter on screenmodel
  2. <100 msCue → scroll and highlight on the pageno model
  3. <1.5 sMid-tour answer, first wordsmodel
  4. laterVoice with live captions (needs a speech provider)model

Presentations never

  • Autoplay, or start without the visitor asking
  • Say something the script and pages don't support
  • Navigate off the site or inject content into the page
  • Hold the visitor: skip, pause and exit are always one tap away
  • Run for AI agents at the agent door (they get the facts directly)
