Control plane 06 · Zavora CLI ships a capability pack

Coding agents propose. Pipelines dispose.

Zavora CLI is Zavora's adk-rust terminal coding agent. A worker model does the work, a bounded planner plans, and every write is approved in place. It can build, test and open a pull request. It cannot sign, publish or touch production: a person signs, and the release train does the rest.

A worker and a bounded planner

The worker owns the conversation, tools and edits. The planner (plan_work) has no tools, runs one iteration, and has a budget of 4 calls per process.

Approvals in place

Reads auto-approve. Writes show a diff and commands show the command line. The model cannot approve itself: approved is stripped from its arguments.

A guard near production

The agentrix-guard hook blocks publish to stable, applies, promotions, freezes, terraform apply and production kubectl. agentrix mcp serve offers reads and proposals only; even --yolo cannot approve a card, which needs a person's passkey or authenticator code.

Honest gap

Zavora CLI has no Vultr or OpenAI-compatible provider today, and its shell has no OS sandbox. Both are listed for its owners in 08 §12 (ZC1, ZC2); hosted dev rooms cover the sandbox.

What happens next

The train, then the owner.

The signed pack starts on ring 0, Zavora's own sites. From ring 1 on, owners who use Bookings see a card in their console. A new capability always needs the owner's yes; they can also start it lower than the pack suggests.
