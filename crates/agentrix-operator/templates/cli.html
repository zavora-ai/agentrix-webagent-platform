What a coding agent may do near production

the same for every coding agent
It can
  • Read the repository, run tests and evals in local sealed rooms
  • Show a diff before every write and the command line before every command
  • Open a pull request and propose a pack version
It never
  • Holds production credentials, signing keys or approval rights
  • Publishes to the stable channel, promotes a ring, freezes a site or applies infrastructure
  • Approves a card: that needs a person's passkey or authenticator code

Then the owner decides

a pack that adds a capability

When a pack version adds a tool or widens what a WebAgent can do, each site's Chief WebAgent offers it as a card with the capability diff: what's new, what stays the same, and the level it starts at. Only the owner installs it, with their passkey or a code. Nothing has been offered yet.
