Three Vultr VMs on one VPC. The control VM runs the site edge, the console, the Move and the Model Gateway, which is the only process holding a model key. The sandbox VM, a VX1, runs every untrusted job in gVisor rooms, holds no secrets and accepts nothing from the internet; each room’s only way out is its own egress proxy with the job’s allowlist. The fixture VM serves Zavora’s infected WordPress for the gauntlet. Every model call goes to Vultr Serverless Inference by purpose once the switch gate has passed; until then the pipeline is validated on Claude, with embeddings and rerank already on Vultr. Remove the bracket only when the switch-gate receipt exists. Every routing change is a signed routing.changed receipt the owner sees; the first, “Models in use, on anthropic”, is live. Object Storage is live: node mirrors every content-store blob and every signed receipt to a bucket in Amsterdam (ams1) each minute, and reads a lost file back, checked against its digest. Its keys are a systemd credential, never in node’s environment. The whole substrate is created from the repo with deploy/provision.sh. The same binaries are designed to run as a fleet on VKE for the managed service.
